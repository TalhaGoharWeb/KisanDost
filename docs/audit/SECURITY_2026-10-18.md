# Kisan Dost — Security Audit (2026-10-18, Phase 6)

**Auditor scope:** `android/` (owner) + read-only review of `lib/` where a
native surface touches it. `lib/` edits belong to sibling workers.
**Branch:** `prod-readiness`.

## 1. Threat model

Kisan Dost is a **single-user, offline-first, Urdu-only** farming diary.
No INTERNET permission by design, no accounts, no backend, no Firebase/
Supabase, no push. The adversary model is:

- **Local data at rest** — the phone is lost/stolen, or a malicious app on
  the same device tries to read app data.
- **Supply chain** — a compromised/malicious dependency smuggles network or
  exfiltration capability into the APK.
- **Physical access to a locked phone** — alarm notifications and the
  full-screen alarm activity are deliberately visible over the keyguard.

Out of scope (no network exists to attack): TLS, API auth, server-side
validation, account takeover. The app's financial records are sensitive to
the farmer, but there is no multi-user privilege boundary to defend.

## 4. Findings

### F1 (info) — third exported component not named in functional audit §10

`AndroidManifest.xml` exports **three** components, not two:

- `.MainActivity` (`exported=true`, MAIN/LAUNCHER) — expected.
- `.BootReceiver` (`exported=true`, intent-filter limited to
  `BOOT_COMPLETED` / `LOCKED_BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` /
  `QUICKBOOT_POWERON` (+HTC variant)). Spoofed broadcasts are rejected by an
  explicit action allowlist in `onReceive` (`BootReceiver.kt:16-25`) —
  exported is *required* for the OS to deliver boot broadcasts. Safe.
- `com.dexterous.flutterlocalnotifications.ScheduledNotificationBootReceiver`
  (`exported=true`, system boot actions only). This is the
  `flutter_local_notifications` v18 plugin's documented receiver, present
  since the initial commit. It only receives OS-protected broadcasts
  (`BOOT_COMPLETED` cannot be spoofed by third-party apps;
  `MY_PACKAGE_REPLACED` is delivered only to the replaced package).
  **Exposure: negligible. No change recommended.** Functional audit §10's
  "only MainActivity + BootReceiver" line is corrected by this report.

All other components (`AlarmReceiver`, `AlarmService`, `AlarmActivity`,
`FileProvider`) are `exported=false` with intent-filters absent or internal.
`allowBackup="false"`. No custom-scheme deep links.

### F2 (info, owner decision — documented, NOT changed) — lock-screen data exposure

- `AlarmService.kt:202`: notification channel sets
  `lockscreenVisibility = Notification.VISIBILITY_PUBLIC` and
  `setBypassDnd(true)`; notification content text = the task title.
- `AlarmActivity` uses `setShowWhenLocked(true)` / `setTurnScreenOn(true)`
  and displays task title, description, date/time and recurrence buttons
  **over the keyguard** (exported=false, so only reachable via the
  full-screen intent).
- Mitigating control already in place: `MainActivity` deliberately does
  **not** show over the lock screen (`MainActivity.kt:22-29` comment) —
  the full app (financial records, parties, inventory) is unreachable from
  a locked phone. The setAlarmClock "show" PendingIntent targets
  MainActivity, which stays behind the keyguard.

This is the product's intended alarm behavior for a farmer's personal
device (single-user threat model). Redaction would be an owner decision;
behavior intentionally left unchanged.

### F3 (info) — Cloudflare Web Analytics beacon token in git history

**Outside this worker's bounded sweep (`lib/` + `android/`), but flagged:**
commit `69b6438` ("Activate Cloudflare Web Analytics with owner token",
2026-10-18) writes `cloudflareToken: "043b674c6fb2445fa52be7431f88af1c"`
into `docs/config.js`. This is a **public site identifier by design**
(embedded in public web pages; it grants no account access), and it is
already published on the live GitHub Pages site — so git history adds no
new exposure. Worst case is third-party analytics-event spoofing for that
property. **Severity: informational.** If the repo is ever scrubbed for
"no secrets in history," this token would need a history rewrite, but it
is not a credential leak. The owner-pasted contact email in the same
config (`muhaqqiqcreates@gmail.com`) is a deliberate public contact
detail, not a secret. **Flagged for the coordinator; no action taken.**

## 5. Re-verification results (all PASS)

- **Permissions:** 10 declared, all alarm/notification/power related
  (`RECEIVE_BOOT_COMPLETED`, `VIBRATE`, `WAKE_LOCK`, `POST_NOTIFICATIONS`,
  `SCHEDULE_EXACT_ALARM`, `USE_EXACT_ALARM`, `USE_FULL_SCREEN_INTENT`,
  `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, `FOREGROUND_SERVICE`,
  `FOREGROUND_SERVICE_MEDIA_PLAYBACK`). **No INTERNET**, and
  `usesCleartextTraffic="false"` + `network_security_config.xml`
  (`cleartextTrafficPermitted="false"`) provide defense in depth. Zero
  `https://` literals or `java.net`/OkHttp/Retrofit/HttpClient usage in
  Kotlin sources.
- **MethodChannel validation:** every `taskId`-taking method null-checks
  (`BAD_ARGUMENT` on missing); `scheduleTestAlarm` builds its own fixed
  task (no Dart-controlled fields reach the scheduler); settings methods
  take no arguments. No string is ever turned into a shell command,
  file path, or SQL.
- **Share path:** `shareApkFile()` stages a **fixed-name** copy
  (`kisandost-share.apk`) of `packageCodePath` into the private cache dir —
  no Dart argument influences the shared path, so the database/backups
  cannot be redirected into the share. FileProvider is `exported=false`
  with per-share `FLAG_GRANT_READ_URI_PERMISSION`.
- **PendingIntents:** every `PendingIntent` in the native stack uses
  `FLAG_UPDATE_CURRENT or FLAG_IMMUTABLE` (SDK ≥ 23); no mutable
  PendingIntents anywhere (`AlarmService.kt:82-111`,
  `AlarmScheduler.kt:118-146`).
- **Broadcast receivers:** `AlarmReceiver` (exported=false) validates
  `taskId != -1`, wraps work in a 10s wake lock with try/finally release;
  notification actions (complete/snooze) hit only the app-private DB.
- **Native SQL:** `DatabaseHelper.kt` uses parameterized `db.query` /
  `db.update` with `?` placeholders exclusively (`"id = ? AND deleted_at
  IS NULL"`); the only `execSQL` is the static `PRAGMA foreign_keys = ON`.
  Soft-delete is respected on every native query (trashed tasks invisible
  to the alarm subsystem).
- **Backup import (Dart, read-only):** `importBackupFile` derives the
  destination from an internally generated timestamped name
  (`_uniqueBackupPath`); the user-picked path is only *read from*, never
  used as a write target — **no path traversal**. `verifyBackup`
  (magic bytes, integrity_check, schema floor, SHA-256) runs before the
  copy is accepted; failed imports clean up partial copies.
- **Signing:** `android/app/build.gradle.kts` reads `key.properties`
  null-on-absent with **no embedded fallback passwords**; `release`
  buildType pins `signingConfig = release` (never debug-signs), with R8
  minify + shrinkResources and `Log.d/v` stripping. `android/key.properties`
  and any `*.keystore` are gitignored (root `.gitignore` and
  `android/.gitignore`) and **untracked** (`git ls-files` grep: empty);
  `git log --all` shows they were **never committed**.
- **Secrets sweep:** `git log -p` over all 110 commits bounded to
  `lib/` + `android/` — no `password`/`secret`/`api_key`/`token`/`bearer`/
  private-key assignments; no `.env`/`.pem`/`credentials` files added in
  history; current tree grep for key-like literals: **0 hits. CLEAN.**

## 6. Accepted risks (owner decisions, unchanged)

1. **Unencrypted plaintext backups** (carried from prior audits) —
   single-user offline model; user exports are their own files.
2. **Lock-screen alarm visibility** (F2 above) — intended product behavior.
3. **In-app update is not implemented** — per strict instructions, NOT
   addressed by adding network capability here.
4. **`filepaths.xml` declares broad roots** (`files-path` / `cache-path` /
   `external-files-path` each at `.`) — inert without a granted URI; shares
   always target single fixed files with explicit grant flags.
